# Задание: перенос точного предпросмотра (docx-preview) на боевой рабочий экран

> Самодостаточный бриф для нового чата. Контекст прошлой сессии здесь весь.
> Цель — НЕ переписывать существующие инструменты ИИ/редактирования, а **встроить
> точный предпросмотр** и связать его с тем, что уже есть.

## Суть и решение (уже принято владельцем)

Сейчас предпросмотр договоров рендерится через TipTap (`document-viewer.tsx`) и
**теряет оформление** загруженных Word-документов (mammoth отдаёт «семантический»
HTML — слетают выравнивание, отступы, стиль нумерации, маркеры). Мы это латали
эвристиками — это тупик.

**Найдено рабочее решение (проверено на прототипе, владельцу зашло):**
рендерить документ библиотекой **docx-preview** (npm, **Apache-2.0, бесплатно для
коммерции**, уже установлена, v0.4.0). Она рисует `.docx` **1-в-1, как в Word**.

**Ключевой архитектурный принцип: предпросмотр = тот самый `.docx`, который скачается.**
- **Загруженный Word** → docx-preview рисует **оригинальный `.docx`**.
- **Созданный/изменённый ИИ** → содержимое → наш конвертер `convertToDocx`
  (`packages/shared/src/formatting/html-docx-converter.ts`) → `.docx` → docx-preview.
- Значит предпросмотр и скачивание **идентичны по определению** (чинит старую
  проблему «в предпросмотре одно, в скачанном DOCX другое»).

## Что уже сделано в прошлой сессии (переиспользовать/ориентироваться)

1. **docx-preview установлена** (`apps/web/package.json`).
2. **Прототип-страница**: `apps/web/src/app/(app)/docx-preview-test/page.tsx`
   - загрузка `.docx` → точный рендер (`renderAsync`), опции рендера подобраны;
   - **ручное редактирование** = `contentEditable` прямо на рендере (кнопка
     «Редактировать») — печатаешь по документу, оформление сохраняется;
   - **ИИ-правка/переписывание** через кнопки, результат перерисовывается.
3. **Прототип-эндпоинт ИИ**: `apps/web/src/app/api/docx-preview-ai/route.ts`
   - `.docx` → HTML (mammoth) → **наш существующий `editDocument`** → `convertToDocx`
     → отдаёт `.docx`. То есть ИИ-движок НЕ переписывался — переиспользован.

> Прототип — служебные роуты `/docx-preview-test` и `/api/docx-preview-ai`, в
> прод-поток НЕ подключены. Их можно использовать как референс и потом удалить.

## Что нужно сделать (само задание)

Встроить точный предпросмотр в **боевой рабочий экран**
`apps/web/src/app/(app)/documents/[id]/work/page.tsx`, сохранив ВСЁ, что там есть:
- справа — **тот же ИИ-чат** (режимы «Правка»/«Вопрос» + анализ/риски), он уже
  работает через `/api/versions/[id]/chat` (SSE) и `editDocument`;
- сверху — **те же кнопки**: Сохранить, Скачать, «Переписать заново», статус версии;
- **тулбар редактирования** (`apps/web/src/components/editor-toolbar.tsx`:
  жирный/курсив/H2/H3/списки/стиль нумерации/выравнивание) — сохранить как есть;
- **добавить кнопку «Редактировать»** (ручной режим на точном рендере).

Заменяется только сам **рендер предпросмотра**: вместо TipTap — docx-preview.

### Обязательный фундамент (сделать ПЕРВЫМ)

**Сохранять оригинальный `.docx` при загрузке.** Сейчас его выбрасываем — при
загрузке файл парсится в браузере (mammoth) и сохраняется только HTML
(`uploadedContent`), а бинарник теряется. docx-preview рисует именно `.docx`.
- Загрузка: `apps/web/src/app/(app)/documents/upload/page.tsx` → `POST /api/documents`
  (`apps/web/src/app/api/documents/route.ts`, поле `uploadedContent`).
- Хранилище: `apps/web/src/lib/storage.ts` (`STORAGE_DIR`, `saveFile`, `versionFileKey`).
- Нужно: класть оригинальный `.docx` в хранилище рядом с версией и отдавать его
  для предпросмотра. **Уже загруженные ранее документы оригинала не имеют** —
  им точный вид задним числом недоступен (это ок, деградируем на текущий рендер).

### Порядок работ (согласован владельцем)

1. **Фундамент**: сохранение оригинального `.docx` при загрузке.
2. **Копия рабочего экрана** на служебном роуте (напр. `/documents/[id]/work-v2`):
   слева docx-preview, справа тот же чат/ИИ, те же кнопки/тулбар, кнопка
   «Редактировать». Подключить к **существующим** эндпоинтам (не плодить новые
   без нужды). НЕ трогать живой рабочий экран, пока не готово.
3. Когда связка работает end-to-end на копии — **свап** в боевой
   `documents/[id]/work/page.tsx` одним переносом.

## Как связать три режима (важно для точности)

- **Просмотр**: docx-preview(итоговый `.docx`) — как в Word.
- **Ручная правка**: `contentEditable` на рендере → сохраняет исходный вид.
  При сохранении версии — сериализовать правки (см. ниже про модель контента).
- **ИИ-правка/вопрос**: **существующий** движок:
  - `editDocument` (`apps/web/src/lib/ai/gigachat-provider.ts`) + блочные операции
    `apps/web/src/lib/doc-blocks.ts` (REPLACE/INSERT/DELETE, вычитывает весь
    договор, пересчитывает нумерацию/суммы, умеет удалять пункт/приложение);
  - полный rewrite — существующая фича REWRITE (цены в `lib/token-pricing.ts`);
  - результат → `convertToDocx` → docx-preview (= то, что скачается).

**Честный нюанс, который надо держать в голове:** пиксель-в-пиксель как оригинал
остаётся только при просмотре и **ручной** правке. После **ИИ**-правки документ
пересобирается нашим `convertToDocx` → вид «нашего конвертера» (чистый юр-формат,
= скачивание). Владелец это видел и принял. Для точечных ИИ-правок в будущем можно
рассмотреть применение изменений прямо на рендере (find/replace), но это не блокер.

## Известные моменты (владелец отметил, учесть при переносе)

1. **Нумерация иногда сбивается после ИИ-правки** — на прототипе после точечной
   правки «Предмет Договора» и «Обязательства сторон» оба показались как «1.»
   вместо 1 и 2. Это блочный движок правок (`doc-blocks` / промпт renumber в
   `editDocument`) — стоит проверить и усилить перенумерацию разделов/подпунктов.
2. **Таблица перерендеривается** после ИИ-правки (docx пересобирается целиком) —
   не критично, но по возможности не дёргать таблицу без нужды.
3. **Маркеры списков `□`** — docx-preview не подгружает символьный шрифт
   (Wingdings/Symbol), маркеры показываются «тофу». Мелочь: подгрузить символьный
   шрифт или маппить маркеры.
4. Заголовки/нумерация из загруженного Word — показывать **как в оригинале** (в
   т.ч. нестандартные «0.1, 0.2»); это фича точности, не баг. Правку нумерации
   делает ИИ по запросу, а не автоструктурирование при загрузке.

## Модель контента и версии (append-only)

- Версии — **только добавлять** (правило проекта, `CLAUDE.md`). Правка = новая версия.
- Сейчас контент версии — HTML (`Version.content`), сборка для показа —
  `assemblePresentation` (`apps/web/src/lib/presentation-content.ts`), отдаётся
  через `GET /api/versions/[id]`.
- Продумать: для загруженных хранить и оригинальный `.docx` (для точного показа),
  и HTML-контент (для ИИ-правок и версий). При ручной правке на рендере —
  сериализовать в HTML для сохранения новой версии.

## Технические заметки

- **CSP строгий** (`apps/web/next.config.ts`): `script-src 'self' 'unsafe-inline'`,
  внешние CDN запрещены. docx-preview бандлится (это ок, 'self'). Картинки —
  `useBase64URL: true` (img-src data: разрешён).
- **docx-preview — только браузер**: грузить динамически (`await import('docx-preview')`),
  клиентский компонент (`'use client'`).
- **Опции рендера** (из прототипа): `inWrapper, breakPages, experimental,
  renderHeaders/Footers/Footnotes, useBase64URL`.
- **Деплой**: push в `main` → авто-деплой на `app.dogodoc.ru` (~2–5 мин). Перед
  пушем — `pnpm --filter web build` локально (сборка обязана пройти).
- **Проверка на проде**: владелец залогинен, тестирует вживую; агент может гонять
  через браузер-инструменты, но загрузку файлов делает владелец.
- Коммиты — **на русском**, в конце `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.

## Критерий готовности

На боевом рабочем экране: договор (загруженный или созданный ИИ) показывается
**как в Word** (= скачивание), работает **ручная** правка (кнопка «Редактировать»),
**та же** правая ИИ-панель (Правка/Вопрос/Анализ) правит документ, тулбар и кнопки
Сохранить/Скачать/версии — на месте. Ничего из существующего ИИ не переписано —
только встроен новый рендер и связан с ним.
