# Физлица и самозанятые как стороны договора

> Дата: 2026-08-20
> Статус: дизайн согласован, готов к плану
> Область: Профили («Мои реквизиты») + Контрагенты + рендер шапки/реквизитов

## Проблема

Сервис умеет работать со сторонами-организациями (ИП, ООО, АО, АНО, ПАО, ЗАО), но не поддерживает **физическое лицо** и **самозанятого** как сторону договора. Между тем это частые сценарии: ИП↔физлицо, физлицо↔физлицо, договор с самозанятым.

Текущее состояние (по разведке кода):
- `Profile` уже имеет `ProfileType.INDIVIDUAL`, кнопку типа и превью, **но** построитель шапки `buildPartyPreambleParts` (`apps/web/src/lib/html-document.ts`) не имеет ветки под физлицо — профиль-физлицо рендерится как юрлицо («в лице …, действующего на основании Устава»).
- `Counterparty` **вообще не имеет поля типа**: тип угадывается эвристикой `kpp ? COMPANY : SOLE_PROPRIETOR`. Ветки физлица нет.
- Нигде в схеме нет паспортных полей — ключевого идентификатора физлица.

## Нормативная опора

Единого акта с точным списком полей физлица в договоре в РФ нет; требования складываются из:

- **ГК РФ ст. 161** — сделки граждан между собой на сумму > 10 000 ₽ требуют письменной формы (договор физлицо↔физлицо, как правило, письменный).
- **ГК РФ ст. 160, 434** — письменная форма = документ, подписанный лицами, совершающими сделку. Физлицо подписывает **лично** → в шапке нет «в лице… на основании…»; раздел «Подписанты» для физлица/самозанятого не нужен.
- **ГК РФ ст. 21** — полная дееспособность с 18 лет (отдельного поля не заводим).
- Идентификация стороны (ФИО + паспорт) — обычай делового оборота; паспорт по ПП РФ № 828.
- **152-ФЗ** — паспорт/адрес/ИНН физлица это ПДн. Хранение паспорта контрагента-физлица пользователем опирается на «обработку для исполнения договора» (ст. 6 ч. 1 п. 5) — отдельный поток согласий в этой задаче **не строим** (правовой флаг для будущей Фазы 15). Перед ИИ паспорт маскируется.
- **422-ФЗ (НПД)** — для самозанятого паспорт **не обязателен**; идентификация через ФИО + ИНН + статус плательщика НПД (справка КНД 1122035 — опционально).
- **ГОСТ Р 7.0.97-2016** — регулирует оформление (слой decor), а не состав полей стороны. К выбору полей физлица не применяется.

## Решения

### Типы сторон
Переиспользуем `ProfileType`, добавляем `SELF_EMPLOYED`. Тот же enum вешаем на новое поле `Counterparty.type`.

Итоговый набор: `INDIVIDUAL` (Физлицо), `SELF_EMPLOYED` (Самозанятый), `SOLE_PROPRIETOR` (ИП), `COMPANY` (ООО/АО), `ANO`, `PAO`, `ZAO`.

### Состав полей

**Все поля свободные (необязательные).** Валидация проверяет только *формат* заполненного значения (например, ИНН — 12 цифр, серия паспорта — 4 цифры), но не требует заполнения. Пустые поля просто не попадают в шапку/реквизиты. Ниже — какие поля показываем для каждого типа.

**Физлицо (`INDIVIDUAL`):**
- ФИО (`name`)
- Паспорт: серия (4), номер (6), кем выдан, дата выдачи, код подразделения (`NNN-NNN`)
- Адрес регистрации (`legalAddress`, в UI переименован)
- ИНН (12 цифр)
- Фактический адрес (`actualAddress`, если отличается)
- Телефон, email
- Банковские реквизиты (`BankDetail`)

**Самозанятый (`SELF_EMPLOYED`)** — по 422-ФЗ акцент на ИНН/НПД:
- ФИО
- ИНН (12 цифр)
- Дата постановки на учёт по НПД (`npdRegisteredDate`)
- Паспорт (все поля)
- Адрес регистрации, фактический адрес, контакты, банк

Для обоих типов **скрываются** КПП и ОГРН. Ни одно поле не обязательно к заполнению.

### Изменения схемы Prisma
`apps/web/prisma/schema.prisma`

- `enum ProfileType` → добавить `SELF_EMPLOYED`.
- `Counterparty` → добавить `type ProfileType` (не nullable; миграция проставляет существующим строкам `kpp ? COMPANY : SOLE_PROPRIETOR`).
- Новые поля в **обе** модели `Profile` и `Counterparty`:
  - `passportSeries String?`
  - `passportNumber String?`
  - `passportIssuedBy String?`
  - `passportIssueDate DateTime?`
  - `passportDeptCode String?`
  - `npdRegisteredDate DateTime?`
  - `actualAddress String?`
- `Profile` → добавить `phone String?` (у `Counterparty` уже есть).
- Миграция: `add_individual_parties`. Данные существующих профилей/контрагентов не теряются; проставляется только `Counterparty.type`.

### Рендер шапки и реквизитов
`apps/web/src/lib/html-document.ts`

- **`buildPartyPreambleParts`** — явная ветка `INDIVIDUAL`/`SELF_EMPLOYED` для **обеих** сторон. Формулировка:
  > «…**Фамилия Имя Отчество**, паспорт <серия> № <номер>, выдан <кем выдан> <дата>, зарегистрирован(а) по адресу <адрес регистрации>, именуемый(ая) в дальнейшем «<Роль>», с <одной/другой> стороны…»
  Без основания полномочий. Для `SELF_EMPLOYED` добавляется «, применяющий(ая) специальный налоговый режим „Налог на профессиональный доход“». Если паспорт у самозанятого не заполнен — паспортный фрагмент опускается, остаётся ФИО + ИНН.
- **`buildPartyLines`** (блок «Реквизиты и подписи сторон») — использовать `party.type` вместо эвристики `!party.kpp`. Для физлица/самозанятого: ФИО, паспорт, адрес регистрации, ИНН (если есть), контакты, банк (если есть); **скрыть** КПП/ОГРН. Для самозанятого — акцент ИНН + строка НПД.
- Пробросить тип и паспортные поля контрагента в `CounterpartyData` (`apps/web/src/lib/ai/types.ts`), `apps/web/src/lib/party-data.ts`, `apps/web/src/lib/presentation-content.ts`. `UserProfileData` уже имеет `type` — дополнить паспортными полями.

### UI
- **`apps/web/src/app/(app)/requisites/page.tsx`** — добавить кнопку типа «Самозанятый»; паспортный блок для `INDIVIDUAL`/`SELF_EMPLOYED`; поле `phone`; для самозанятого поле НПД. (Рендер-баг физлица чинится в билдере.)
- **`apps/web/src/app/(app)/counterparties/new/page.tsx`** и **`[id]/page.tsx`** — добавить выбор типа кнопками (как в реквизитах); условно скрывать КПП/ОГРН и **раздел «Подписанты»** для физлица/самозанятого; показывать паспортный блок; авто-подсказка типа по длине ИНН (не форсируя выбор). Живое превью — через общий компонент.
- **`apps/web/src/components/requisites-preview.tsx`** — расширить рендер физлица (уже частично умеет) паспортом и веткой самозанятого.

### ПДн и валидация
- **`apps/web/src/lib/anonymize.ts`** — в `maskPartyForAI` добавить в `secretKeys`: `passportSeries`, `passportNumber`, `passportIssuedBy`, `passportIssueDate`, `passportDeptCode`, `npdRegisteredDate`. (Текстовый `anonymizeForAnalysis` уже маскирует паспорт.)
- **`apps/web/src/lib/validation.ts`** — добавить `validatePassportSeries` (4 цифры), `validatePassportNumber` (6 цифр), `validatePassportDeptCode` (`NNN-NNN`). Проверяют только формат непустого значения; пустое значение считается валидным (поля необязательны). `validateInn` уже поддерживает 12 цифр. Дата выдачи — не в будущем (в UI).
- **API zod** — `apps/web/src/app/api/counterparties/route.ts` и `[id]/route.ts`: добавить `type` (enum) и паспортные поля, сохранять их (сейчас `orgForm` принимается, но не пишется — заменить на `type`). `apps/web/src/app/api/profiles/route.ts` и `[id]/route.ts`: добавить `SELF_EMPLOYED` в enum и паспортные поля.

### Удобства «от себя»
- Авто-подсказка типа по длине ИНН (10→организация, 12→физлицо/ИП/самозанятый) как подсказка, не жёсткий выбор.
- Поле «Фактический адрес (если отличается от регистрации)».
- Живое превью «Как в документе» на форме контрагента.
- Валидация паспорта и даты выдачи.

## Покрываемые кейсы
Физлицо↔юрлицо/ИП, физлицо↔физлицо, самозанятый в любой роли (Продавец/Покупатель/Заказчик/Исполнитель) — и как «Мои реквизиты», и как контрагент.

## Вне области (YAGNI)
- Поток согласий 152-ФЗ на паспорт контрагента (правовой флаг → возможная Фаза 15).
- Проверка дееспособности/возраста, загрузка сканов паспорта, DaData-автозаполнение.
- Импорт справки НПД из «Мой налог».
