# Разведка API pravo.gov.ru (живой тест) — итоги для Плана 2

> Дата: 2026-08-24. Проверено вживую curl'ом против `publication.pravo.gov.ru`.
> Цель: понять, что и как реально отдаёт официальный API, до написания кода забора.

## Что доступно (проверено вживую)

**База API:** `http://publication.pravo.gov.ru` — работает, отдаёт JSON. Есть Swagger:
`/swagger/v1/swagger.json` (полная карта эндпоинтов).

Ключевые эндпоинты:
- `GET /api/PublicBlocks` — блоки публикации (president, assembly, government, …) с `id`/`code`.
- `GET /api/DocumentTypes` — типы актов с GUID. Нужный: **«Федеральный закон» = `82a8bf1c-3bc7-47ed-827f-7affd43a7f27`**.
- `GET /api/Documents?Block=&DocumentTypes=&Name=&Number=&DocumentDateFrom=&PublishDateFrom=&PageSize=100&Index=1`
  — поиск/список актов с богатыми фильтрами (тип, номер, имя, даты, полнотекст `DocumentText`). Возвращает
  `items[]` с метаданными: `eoNumber`, `complexName`, `name`, `number`, `documentDate`, `documentTypeId`,
  `pdfFileLength`, `pagesCount`, `id`. **`PageSize` принимает 100/200** (мелкие значения дают 400).
- `GET /api/DocumentText?eonumber=…` — флаг наличия текста (`true`/`false`), НЕ сам текст.
- `GET /document/text/{eoNumber}` — **HTML-страница с текстом акта** (когда текст есть).
- `GET /{controller}/pdf/{eoNumber}` — PDF-образ.
- `GET /OpenData/list.json` + `/OpenData/7710349494-legalacts-{code}/…csv` — bulk-выгрузки метаданных за период (напр. `legalacts-30` — за 30 дней).

## Главные ограничения (критично для стратегии)

1. **Это поток ПУБЛИКАЦИЙ, а не свод.** Каждый `eoNumber` = отдельный опубликованный акт. Кодекс (ГК и т.п.)
   тут представлен как исходный закон + сотни «О внесении изменений…». **Готового консолидированного текста
   кодекса, разбитого по статьям, API не отдаёт.** (Пример из свежей выдачи ФЗ: `334-ФЗ` — «О внесении
   изменений в отдельные законодательные акты».)
2. **Текст есть не у всех.** Из 12 свежих ФЗ машиночитаемый текст (`/document/text/…`) — у ~6; остальное
   только PDF-скан. То есть даже поштучно текст доступен примерно у половины актов.
3. **Текст отдаётся HTML-страницей**, а не чистым текстом/структурой — потребуется извлечение и разбор.
4. **ИПС «Законодательство России»** (где лежат консолидированные тексты) чистого API не имеет — только
   `/proxy/ips/?searchlist` на windows-1251, реверс-инжиниринг которого хрупок.

## Вывод: что API реально может и не может

| Задача | publication.pravo.gov.ru | Вывод |
|--------|--------------------------|-------|
| Мониторинг изменений: узнать, что вышел закон, меняющий наш акт | ✅ `/api/Documents` по номеру/имени/дате | **Годится — это сила API** |
| Получить консолидированный текст ГК/ФЗ по статьям для ядра | ❌ отдаёт поправки и PDF, не свод | **Не годится — нужен другой источник** |
| Bulk-метаданные опубликованного за период | ✅ OpenData CSV | Годится для реестра публикаций |

## Реалистичная стратегия Плана 2

**Разделить наполнение на два механизма:**

1. **Ядро (консолидированный текст 15 актов) — разовый seed из консолидированного источника.**
   API pravo.gov.ru его не даёт. Варианты источника текста: (A) парсинг ИПС `pravo.gov.ru/ips` (HTML,
   хрупко); (B) разовый курируемый импорт текста 15 актов из чистого структурированного источника.
   Это соответствует спеке (seed ядра + флаг ручной проверки).

2. **Автообновление — воркер мониторинга через `/api/Documents`.**
   Периодически спрашиваем API: не вышли ли акты, меняющие отслеживаемые 15 (по номеру/имени/дате).
   Нашли — создаём отметку «требуется обновление редакции» (флаг ручной проверки в админку) и, где текст
   доступен, тянем `/document/text/{eoNumber}`. Полностью автоматический merge поправки в текст кодекса —
   вне v1 (честный компромисс из спеки).

## Открытый вопрос владельцу (нужно решить до кода)

**Откуда берём консолидированный текст 15 актов ядра?**
- (A) Парсер ИПС pravo.gov.ru/ips — «по-честному из госисточника», но HTML-скрейп, хрупко, требует
  отдельной разведки ИПС.
- (B) Разовый курируемый импорт текста 15 актов (единоразово, дальше API следит за изменениями) —
  быстрее и надёжнее для старта, «API-автообновление» остаётся в виде мониторинга поправок.

Рекомендация: **B на старте** (быстро получаем рабочую базу ядра), мониторинг изменений через API —
сразу; парсер ИПС (A) — как последующее улучшение, если понадобится полностью автоматический тексто-забор.

# ДОПОЛНЕНИЕ (2026-08-24, вторая разведка): найден JSON-API ИПС с текстами

Первая разведка ошибочно закрыла вопрос выводом «консолидированных текстов не достать».
Проверялся только раздел «Официальное опубликование». У **ИПС «Законодательство России»**
есть собственный JSON-API, который отдаёт действующие консолидированные тексты.

## Хост и эндпоинты

База: `http://ips.pravo.gov.ru` (SPA, за ней JSON-API).

| Эндпоинт | Метод | Что отдаёт |
|---|---|---|
| `/api/ips/legislation/search.json` | POST `{"text": "..."}` | поиск актов: `nd`, `name`, `state`, `docdate` |
| `/api/ips/legislation/document_card.json?nd=` | GET | карточка: название, состояние («Действует с изменениями») |
| `/api/ips/legislation/document_content?nd=` | GET | **структура документа** |
| `/api/ips/legislation/documenttext?nd=` | GET | **полный текст** (HTML в поле `doctext`) |

## Формат идентификатора

`nd` нового API = `1000000000` + старый номер ИПС.
Пример: ГК ч.1 — старый `102033239`, новый **`1000000000102033239`** (проверено).

Известные: ГК ч.1 `1000000000102033239`, ТК РФ `1000000000102074279`,
152-ФЗ `1000000000102108261`, КоАП `1000000000102074277`.

## Структура (`document_content`) — главное преимущество

Массив `data`, элементы с полями:
- `unit` — тип единицы словами: `раздел` / `подраздел` / `глава` / `статья` / `пункт`
- `caption` — «Статья 330. Понятие неустойки»
- `id` — иерархический путь, **номер статьи внутри**: `siii_d1_h23_g2_a330` → статья 330
- `npe`, `np` — якоря абзацев, совпадают с якорями в HTML из `documenttext`

То есть государство отдаёт готовую разбивку по статьям и пунктам — резать текст
регулярками и угадывать границы не нужно.

Проверено на ГК ч.1: 2654 структурных элемента, **473 статьи**, текст 1 МБ,
якоря (`p4239` и т.п.) реально присутствуют в HTML и стыкуются со структурой.

## Почему не готовые датасеты

- **RusLawOD** (304 382 акта, HuggingFace): лицензия **CC BY-NC-SA 4.0 — некоммерческая**,
  проекту не подходит; тексты «как опубликованы» (не консолидированные), срез апрель 2024.
- Корпус СПбГУ (CoJurRC) — академическая лицензия.
- ИПС: официальный источник, актуальная редакция, и официальные тексты законов
  не охраняются авторским правом (ст. 1259 ГК) — юридически чисто для коммерческого сервиса.
