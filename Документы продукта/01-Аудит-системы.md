# Аудит системы «Догодок» — код, UX, дизайн, нагрузка

> Дата: 2026-07-30 · Ветка: main (актуальная, подтянуты последние 7 коммитов)
> Метод: статический аудит кода 4 параллельными агентами (typecheck/lint + чтение всех 40 API-роутов, 20 страниц, схемы БД, инфраструктуры). Живой прод в браузере не прокликивался (нужен вход под аккаунтом).

## Общий вердикт

Продукт сделан **крепко**: авторизация единая (`getUserId`/`requireAdmin`), все 40 роутов проверяют сессию, вход/регистрация защищены rate-limit + блокировкой аккаунта + аудитом, ключи ИИ-операторов шифруются AES-256-GCM, ПДн маскируются перед ИИ, генерация идёт через очередь BullMQ, версии append-only, интерфейс полностью на русском. Большинство кнопок и форм — рабочие, с loading/empty/error-состояниями.

**НО к платному запуску есть 4 блокера и ряд важных рисков.** Ниже — по приоритету. Полные версии — в отдельных файлах отчётов.

## 🟠 Нагрузка и масштабируемость

**Текущий потолок — уровень пилота: ~10–20 одновременных активных пользователей.** Три стены в порядке наступления:

1. **Воркер генерации `concurrency=1`** (`lib/queue.ts:14-16`, `WORKER_CONCURRENCY` не задан в проде) — генерируется 1 документ за раз на всю систему (~40–60 док/час). Главная фича однопоточная.
2. **chat/review/analyze идут мимо очереди**, синхронно в web-процессе, без rate-limit → упрутся в 429 ИИ-провайдера и сокеты.
3. **Нет индексов БД** на `userId` и др. (кроме `LoginAudit`, `AIUsageLog`) → все списки `WHERE userId` — seq scan, деградируют с ростом данных.

Плюс: файловое хранилище `STORAGE_DIR` не смонтировано как общий volume → файлы воркера web не видит и теряются при redeploy; нет rate-limit в nginx; покупка без реальной блокировки строки.

**Быстрые победы (часы работы):**
- `WORKER_CONCURRENCY=3-5` в `docker-compose.prod.yml`
- Миграция с индексами (`Document.userId`, `Version.createdAt/status`, `ChatMessage.versionId`, `Counterparty.userId`, `Transaction.walletId` и др.) — максимальный выигрыш за минимум усилий
- Rate-limit (уже есть `lib/rate-limit.ts` на Redis) на `generate/chat/review/analyze/topup/upload`
- Пагинация в `history`, дефолтный `take` в `documents`
- Убрать N+1 в `counterparties/route.ts` (один `groupBy`)
- nginx: `limit_req_zone` + gzip
- Общий volume под `STORAGE_DIR` для web и worker

**Крупные (проектные):** вынести все ИИ-операции в BullMQ (главный архдолг под нагрузку); горизонтальное масштабирование web + воркеры; файлы → S3; PgBouncer; настоящая блокировка кошелька в purchase.

## 🟡 Кнопки и UX

**9 кнопок-пустышек** (не критичны для основного e2e, но заметны):
- «Забыли пароль?» (`login:228`) — без обработчика
- «Новый документ» primary в карточке контрагента (`counterparties/[id]:537`) — без `onClick` (рабочий дубликат спрятан в меню «…»)
- Кнопки тарифов «Перейти» и «Добавить» +100 ГБ на хранилище (`storage:361,392`) — без `onClick`, но выглядят активными
- Зоны «Загрузить факсимиле/печать» (`requisites:372-373`) — открывают файловый диалог, но файл никуда не уходит (отложенная задача 4.4)
- Кнопка-щит уровня защиты на рабочем экране (`work:1448`) — только индикатор
- «Выйти» (`app-layout:188`) — редиректит на несуществующий `/auth`, спасает только middleware

**Несоответствия цифр:**
- Хардкод **540 ₽** в балансе и на главной (`page.tsx:296,319`, `balance:171,238`) расходится с реальной динамической ценой (`calcVersionPrice` даёт 40–100 ₽)
- «Баланс: 0 ₽ — будет недостаточно» жёстко зашит на шаге создания (`documents/new:1574`) независимо от реального баланса

**Пропущенные error-состояния:** хранилище, история платежей, история версий, пополнение баланса, CRUD реквизитов/подписантов/контрагентов — при ошибке `fetch` UI молчит или считает операцию успешной.

**Соблюдено:** ИИ-чат постоянной колонкой справа (420px); покупка/подпись/статусы бьют по корректным API; append-only версии.

## 🟡 Дизайн (соответствие макету)

- **~12 экранов рендерят серифные заголовки системным шрифтом** (Georgia/Times) вместо Source Serif 4 — используется несуществующий токен `var(--font-serif)` вместо `--font-display` (balance, главная, admin/ai, counterparties, documents, compare, work, check, payments, history, templates, storage). Главный источник визуального рассинхрона.
- **Статус «Оплачено» — зелёный** вместо slate-indigo из макета (`badge.tsx:17`); approved/paid/signed все зелёные и не различаются.
- **Захардкоженные цвета** мимо токенов: `#DC2626/#FEE2E2` вместо `--danger` (`work:1327`), `hover:text-red-500` (`counterparties/[id]:319`) и др.
- **Адаптивность ≤768px сделана только для каркаса** (сайдбар → drawer). На большинстве внутренних страниц `grid-cols-*` не сворачивается: balance, storage, payments, requisites, counterparties, templates, history — без единого `sm:/md:/lg:`.
- **Доступность:** `aria-label` всего в 3 местах — иконочные кнопки (гамбургер, закрытие drawer, меню «…») без доступного имени; `focus-visible` только у Button; вторичный текст `--ink-4` #A09D94 на светлом — низкий контраст для 11px.
- **Дрейф документации:** CLAUDE.md заявляет Next.js 14, фактически `next@16.2.6` + `react@19`.

**Соблюдено:** токены цветов/радиусов/теней перенесены в globals.css корректно, Button/Card/Badge/AppLayout на токенах, шрифты через next/font.

## Рекомендованный порядок работ

1. **Спринт «боеготовность»** (1–3 дня): Б1–Б4 + В1, В2. Без этого нельзя брать деньги и пускать трафик.
2. **Спринт «нагрузка»** (2–4 дня): индексы БД, `WORKER_CONCURRENCY`, rate-limit, пагинация, общий volume. До запуска рекламы.
3. **Спринт «полировка»** (2–3 дня): токен `--font-serif`→`--font-display`, цвет статуса «Оплачено», адаптивность внутренних страниц, устранение хардкода 540 ₽, error-состояния, «мёртвые» кнопки (задизейблить/«Скоро»).
4. **Позже:** вынос ИИ в очередь, S3, доступность, устранение мислейблов.
